# AI Reflection

I gave the AI assistant a compact repository map rather than asking for a blind rewrite. The context included the Assignment 03 Python `can_book` function, its tests, the original AC1-AC6 criteria, and the Assignment 04 requirements. I asked it to preserve booking behavior while adding a fictional multi-room catalog, capacity and equipment filters, responsive feedback, tests, and submission evidence. This context kept the work focused on a small extension instead of unrelated features such as authentication, a database, or live APIs.

Several suggestions were useful. The strongest was separating catalog data, availability rules, filtering, the selected-room service, and browser presentation. That structure made it straightforward to test the original time rules independently from the filtering rules. The AI also proposed boundary tests for 120 versus 121 minutes, touching versus overlapping intervals, and exact capacity versus insufficient capacity. These became executable tests instead of unsupported claims in the report.

I did not accept every suggestion unchanged. One suggestion was to combine room filtering with availability checking in one function. I modified that design because filtering decides which rooms are displayed, while availability decides whether one selected room can host an interval. Keeping the concerns separate makes it clear that the selected room's own bookings are used. I also used minute-number inputs rather than ordinary time inputs so the valid end-of-day value, 1440, remains possible.

I personally verified requirements against the brief, inspected the baseline source, reviewed final module boundaries, ran the test command, and checked key page behavior in a browser. Tests exposed where exact boundaries mattered and required a service-level test for room switching. Next, I would add a clock abstraction, persistent fictional data storage, and multi-viewport browser automation while retaining pure rule tests.
